## 1. 專案總覽

**品牌**：知暖學習工作室（Warm Learning Studio），高雄在地英文教育品牌，服務幼兒到成人英文，核心差異化是「陪伴式學習」與「AI 輔助學習」。

**網站定位**：招生轉換工具，核心轉換動作為「預約諮詢」與「加入 LINE 諮詢」。

**品牌核心訊息**（文案主軸，v6 更新）：
> 知暖陪伴學習者從幼兒到成人，不只是學好英文，更一步步建立自主學習能力，成為能持續成長的終身學習者。

**品牌三大核心價值**（撰寫全站補充文案、行銷素材時建議圍繞這三個主軸展開，而非只強調「英文課程」本身）：
- **陪伴**：每位孩子都值得被理解，學習節奏因人而異
- **自主**：教會孩子如何學，而不只是教什麼內容
- **成長**：英文只是媒介，真正培養的是一生受用的能力

**開發範圍（v7 更新）**：首頁、關於知暖（品牌故事＋創辦人）、課程介紹（Learning Journey 課程地圖）、最新消息（含後台 CMS）、聯絡我們、常見問題、隱私權政策與服務條款，共七個對外頁面 + 一組後台管理系統。

## 2. 技術棧與專案結構

| 項目 | 選擇 |
|---|---|
| 語言 | Rust |
| 前端框架 | Leptos（SSR 模式，確保 SEO 可被搜尋引擎索引） |
| 後端 / HTTP Server | Axum（透過 `leptos_axum` 整合） |
| 非同步執行環境 | Tokio |
| 資料庫 | SQLite |
| 資料庫存取層 | `sqlx`（async，含 compile-time SQL 檢查與 migration 工具） |
| 樣式 | Tailwind CSS |
| 密碼雜湊 | `argon2` crate |
| Session／登入驗證 | `tower-sessions` + `tower-sessions-sqlx-store`（session 存在 SQLite） |
| 圖片處理 | `image` crate（上傳時自動壓縮／產生縮圖） |
| 建置工具 | `cargo-leptos` |
| 容器化 | Docker（Leptos 官方 SSR Dockerfile 範本） |

**專案目錄結構**：

```
zhinuan-studio/
├── Cargo.toml                # workspace 設定
├── app/                      # Leptos 前端 + 共用元件（可 SSR / CSR 共用）
│   ├── src/
│   │   ├── pages/            # 各頁面元件：home.rs, about.rs, courses.rs, news.rs, contact.rs
│   │   ├── components/       # 共用元件：navbar.rs, footer.rs, cta_button.rs, card.rs
│   │   └── lib.rs
├── server/                   # Axum 伺服器進入點
│   ├── src/
│   │   ├── main.rs
│   │   ├── routes/           # admin 路由、API 路由
│   │   ├── db/                # sqlx 連線池、query 函式
│   │   └── auth/              # session、密碼驗證
├── migrations/                # sqlx migration SQL 檔
├── public/                    # 靜態資源（圖片、favicon）
├── style/                     # Tailwind 設定與輸出
└── Dockerfile
```

## 3. 網站架構

### 3.1 分層架構圖

```
Layer 0：網站根目錄
│
├── Layer 1：對外頁面（Public Routes）
│   ├── / 首頁
│   ├── /about 關於知暖
│   ├── /courses 課程介紹
│   ├── /news 最新消息（列表）
│   ├── /news/:slug 最新消息（單篇）
│   ├── /contact 聯絡我們
│   ├── /faq 常見問題
│   └── /privacy 隱私權政策與服務條款
│
├── Layer 2：後台管理系統（Admin Routes，需登入）
│   ├── /admin/login 登入頁
│   ├── /admin 後台首頁（儀表板）
│   ├── /admin/announcements 公告列表
│   ├── /admin/announcements/new 新增公告
│   ├── /admin/announcements/:id/edit 編輯公告
│   └── /admin/contacts 聯絡表單留言列表
│
└── Layer 3：系統層（非頁面，功能性端點）
    ├── /api/contact （POST，聯絡表單送出）
    ├── /uploads/* （靜態圖片檔案伺服器路徑）
    ├── /sitemap.xml
    └── /robots.txt
```

### 3.2 每頁功能總表

| 頁面 | 路由 | 主要功能 | 是否需登入 |
|---|---|---|---|
| 首頁 | `/` | 品牌形象展示、導引至課程／聯絡頁、CTA 轉換 | 否 |
| 關於知暖 | `/about` | 品牌故事、創辦人介紹、教學理念展示 | 否 |
| 課程介紹 | `/courses` | Learning Journey 課程地圖、方案比較 | 否 |

| 最新消息單篇 | `/news/:slug` | 顯示單篇公告完整內容 | 否 |
| 聯絡我們 | `/contact` | LINE／電話資訊展示、聯絡表單送出 | 否 |
| 常見問題 | `/faq` | 展示 FAQ 問答，協助訪客釐清疑慮、降低諮詢門檻 | 否 |
| 隱私權政策與服務條款 | `/privacy` | 顯示個資蒐集與使用說明、服務條款文字 | 否 |
| 後台登入 | `/admin/login` | 帳號密碼登入，建立 session | 否（登入本身） |

## 5. 視覺風格規範

> 本節設計方向以 Henry 提供的首頁 mockup 圖為準（藍白基調、溫暖堅定、專業有信任感）。以下拆解為色票、字體、元件級版型規範，供 Claude Code 逐一對照實作。

### 5.1 整體設計原則

1. **乾淨留白為主**：不使用滿版色塊或密集裝飾，區塊之間靠留白與淺色背景區隔，不用粗重分隔線
2. **膠囊圓角按鈕**：所有主要行動按鈕（CTA）一律全圓角膠囊狀（`rounded-full`），不使用直角或小圓角按鈕
3. **卡片統一風格**：內容卡片一律用大圓角（`16px–20px`）+ 極輕陰影，不用邊框線；hover 時陰影加深、卡片輕微上浮（`translate-y`）營造互動感
4. **圖示走線性風格**：Icon 一律使用單色線條圖示（outline style，非填色 icon），放在淺藍色圓形色塊中央，呈現柔和、不銳利的觀感
5. **色塊分區代替線條分區**：不同區塊用「白底」與「淺藍底」交錯排列來分隔視覺區塊（見 mockup 中「為什麼選擇知暖」為白底、「學生成果與家長好評」為淺藍底），不额外加分隔線
6. **人像攝影風格溫暖自然**：使用生活感、微笑、自然光的教學情境照，避免生硬棚拍感或過度修圖的既視感
7. **單一強調色克制使用**：溫暖金色點綴（`#E8B975`）只用在少數需要「被注意到」的元素上（推薦徽章、hover 強調），大面積仍以藍白為主，避免整頁看起來花俏

### 5.8 動畫與互動規範（v10 新增）

> 技術原則：不引入任何第三方 JS 動畫套件（AOS、GSAP、Framer Motion 等），一律用 Tailwind CSS transition／animation 搭配少量原生 JavaScript（透過 `web-sys` 綁定瀏覽器原生 API，如 IntersectionObserver）實作，維持專案「不依賴外部服務／套件」的原則。所有動畫需尊重使用者的 `prefers-reduced-motion` 設定，該設定開啟時停用或大幅簡化動畫。**漸進增強原則**：任何動畫效果都不能讓內容在 JavaScript 未執行（或執行失敗）時變成不可見或不可讀，SSR 輸出的初始 HTML 本身必須是完整可讀的。

## 6. 功能規格：後台管理系統（CMS）

### 6.1 登入 `/admin/login`
- 表單欄位：帳號、密碼
- **初始管理者帳號**：`warm`／`learning`（僅供開發階段建立初始資料使用；**正式上線前務必更換為更高強度的密碼**，建議至少 12 碼並包含英數混合，可在後台新增「修改密碼」功能，或請 Claude Code 於部署前手動更新資料庫）

- 「新增公告」按鈕連結至 `/admin/announcements/new`

### 6.4 公告編輯表單 `/admin/announcements/new`、`/admin/announcements/:id/edit`

欄位：
- 標題（文字，必填）
- 網址代稱 slug（文字，選填，未填則由標題自動產生，需檢查唯一性）
- 內文編輯器：**採用簡易所見即所得編輯器（rich text editor），提供基本排版按鈕（粗體、換行、項目符號、插入圖片），不需要作者理解 Markdown 或 HTML 語法**
- 封面圖片上傳（拖曳或點擊上傳，限制檔案大小與格式，見第 9 節）
- 發布狀態切換（草稿／發布，UI 用 toggle 開關呈現）
- 發布日期（預設為當下時間，可手動調整為排程未來時間）
- 「儲存草稿」與「發布」兩個送出按鈕

**技術實作要點**：
- 圖片上傳後，後端用 `image` crate 自動壓縮並產生一份縮圖（用於列表頁），原圖與縮圖分別存於 `public/uploads/announcements/`
- slug 自動產生規則：標題轉小寫英數 + 時間戳記，中文標題則直接用公告 ID 作為 slug（因中文不適合直接做 URL slug）

### 6.5 聯絡表單管理 `/admin/contacts`
- 表格列出所有聯絡表單留言：姓名、電話、諮詢課程、送出時間、已讀／未讀狀態
- 點擊可展開查看完整留言內容
- 可標記為已讀／刪除

| `admin_logout()` | 清除 session | 是 |
| `get_all_announcements()` | 後台取得所有公告（含草稿） | 是 |

## 9. 安全性規範

1. **密碼儲存**：僅存 argon2 雜湊值，不存明文，不使用可逆加密
2. **登入保護**：連續 5 次失敗鎖定帳號 15 分鐘（見 6.1）
3. **Session 安全**：session cookie 設定 `HttpOnly`、`Secure`（僅 HTTPS 傳輸）、`SameSite=Lax`
4. **表單防機器人**：聯絡表單與訂閱表單加入 honeypot 隱藏欄位（機器人會自動填入，人類看不到也不會填，後端偵測到該欄位有值即視為垃圾訊息並丟棄）
5. **圖片上傳限制**：僅允許 `jpg`、`png`、`webp` 格式，單檔大小上限 5MB，上傳時重新編碼圖片（避免夾帶惡意程式碼）
6. **輸入驗證**：所有表單輸入於後端 server function 內二次驗證（不可僅信任前端驗證），防止繞過前端直接呼叫 API
7. **SQL 注入防護**：一律使用 `sqlx` 的參數化查詢（query binding），不手動拼接 SQL 字串
8. **後台路徑保護**：所有 `/admin/*` 路由（除登入頁外）均需 middleware 驗證 session 有效性

## 11. 錯誤處理與資料備援

1. **404 頁面**：找不到頁面時顯示自訂錯誤頁，含「返回首頁」按鈕
2. **500 錯誤頁**：伺服器錯誤時顯示友善錯誤訊息（不顯示技術錯誤細節給訪客），後端記錄詳細錯誤 log
3. **表單提交失敗**：前端顯示明確錯誤訊息（如「網路異常，請稍後再試」），不讓使用者以為已送出成功
4. **資料庫備份**：SQLite 資料庫檔案需定期備份，建議：
   - 部署平台設定每日自動快照（依部署平台功能而定）
   - 或於後台新增「匯出資料庫備份」功能，Henry 可手動下載備份檔
5. **上傳圖片遺失防護**：圖片檔案與資料庫需存放於同一持久化儲存空間（persistent volume），避免每次部署後圖片消失

## 12. 部署與 CI/CD

1. 程式碼存放於 GitHub repo：`warmlearning/zhinuan-studio`
