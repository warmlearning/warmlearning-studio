## 1. Email 通知寄送方式

**決定**：使用 **Gmail SMTP** 寄送聯絡表單通知信，不使用第三方轉信服務（如 Resend、SendGrid）。

**理由**：知暖的聯絡表單流量很小（一天頂多數封），Gmail 免費帳號的寄送額度（每日約 500 封）綽綽有餘，不需要為此另外申請服務、也不需要額外費用。

**實作方式**：
- Rust 端使用 `lettre` crate 透過 SMTP 協定寄信
- 寄件帳號使用 `zhinuanwarmstudio@gmail.com`
- **需要 Henry 事前設定**：登入這個 Gmail 帳號 → 開啟兩步驟驗證 → 產生一組「應用程式密碼」（App Password，16 碼），這組密碼會存成環境變數，**不是**登入 Gmail 網頁版的原本密碼
- 收件人與寄件人可以是同一個信箱（自己寄給自己），或之後想指定其他信箱接收也可以

## 2. 環境變數清單

Claude Code 建置時，以下變數不寫死在程式碼裡，一律透過環境變數注入：

| 變數名稱 | 說明 | 範例值 |
|---|---|---|
| `DATABASE_URL` | SQLite 資料庫檔案路徑（本機開發用） | `sqlite://./data/zhinuan.db` |
| `SESSION_SECRET` | Session 加密用的隨機金鑰（至少 64 bytes，建置時隨機產生一次，之後固定不變） | 由 Claude Code 建置時產生 |
| `SMTP_HOST` | Gmail SMTP 主機 | `smtp.gmail.com` |
| `SMTP_PORT` | SMTP 連接埠 | `587` |
| `SMTP_USERNAME` | 寄件 Gmail 帳號 | `zhinuanwarmstudio@gmail.com` |
| `SMTP_APP_PASSWORD` | Gmail 應用程式密碼（見上一節） | 待 Henry 產生後提供 |
| `CONTACT_NOTIFY_EMAIL` | 聯絡表單通知信收件地址 | `zhinuanwarmstudio@gmail.com` |
| `UPLOAD_DIR` | 圖片上傳存放路徑（本機開發用） | `./data/uploads` |
| `PORT` | 伺服器監聽埠 | `8080` |
| `RUST_LOG` | 日誌等級 | `info` |

**安全提醒**：這些變數（尤其 `SMTP_APP_PASSWORD`、`SESSION_SECRET`）**絕對不要**寫進程式碼或 commit 進 GitHub repo，開發階段一律用本機的 `.env` 檔案管理（並把 `.env` 加進 `.gitignore`）。正式環境要用什麼方式管理機密值，等家用主機部署文件確定時再一併補上。

## 4. GitHub 版本控制規範

> 正式部署主機的設定，等家用主機準備好之後再另外製作專屬文件，目前先略過，專注在網站本身的開發。以下只規範開發階段的版本控制方式。

**Repo**：延續現有的 `warmlearning/zhinuan-studio`

**分支策略**：
- `main`：穩定分支，只有每個 Phase 驗證完成、確定沒問題的版本才合併進來
- 開發時另開功能分支，命名格式 `phase-a-project-setup`、`phase-b-homepage` 這類，對應規格書第 13 節的 Phase A～E
- 每個 Phase 做完、驗證沒問題後，發一個 Pull Request 合併回 `main`，即使是自己一個人開發，也建議走這個流程，方便之後回頭查是哪個階段做了什麼改動

**Commit 規範**：
- 訊息開頭標明對應階段，例如 `[Phase A] 建立 Cargo workspace 與資料庫 migration`
- 每完成一個明確的小任務就 commit 一次，不要累積一大包才 commit 一次——階段內也建議切成多個小 commit，之後要退回某個時間點會更精準
- `.gitignore` 需排除：`target/`（Rust 編譯產物）、`.env`（機密環境變數）、`*.db`（本機測試用資料庫檔案，避免測試資料被誤傳上 GitHub）

**定期備份／存檔點**：既然目前沒有正式部署環境，GitHub 本身就是主要的存檔機制。建議至少**每個 Phase 結束都要 push 一次**，不要放在本機太久沒同步，避免電腦端資料遺失。

## 5. 404／500 錯誤頁文案

**404 頁面**：
- 標題：「這個頁面好像不小心迷路了」
- 說明文字：「你要找的頁面不存在，或已經被移動了。」
- 按鈕：「返回首頁」（連結至 `/`）
- 搭配插圖：`illustration-404.png`

**500 錯誤頁**：
- 標題：「系統出了一點小狀況」
- 說明文字：「我們正在盡快處理，請稍後再試一次，或直接透過 LINE 與我們聯繫。」
- 按鈕 1：「返回首頁」
- 按鈕 2：「加入 LINE 諮詢」（連結至 LINE 官方帳號）

## 6. 網站流量分析與 SEO 工具

**決定**：**不使用任何流量分析工具**，不加裝 Google Analytics，也不串接 Google Search Console。網站不依賴任何 Google 帳號或外部追蹤服務。

**影響**：
- 隱私權政策第 4.6 節「Cookie 使用說明」維持原本的版本即可（原文已寫「不會用於追蹤您在其他網站上的行為，也不會用於廣告投放」），不需要再補充分析工具相關文字
- 不需要處理 Cookie 同意橫幅，網站本身也不會使用任何追蹤性質的 Cookie（Session 登入用的 Cookie 是功能性必要 Cookie，跟分析追蹤無關，本來就不受影響）
- 之後若想知道網站流量狀況，可以之後在 Rust 後端自行加一個簡單的造訪記錄（例如記錄每次頁面請求到資料庫），完全在自己掌控的系統內，不依賴外部服務——這個屬於 Phase 2 可選功能，v1 不做
